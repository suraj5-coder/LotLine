# LotLine

**A recall notice names a lot. Which stores and warehouses actually have it?**

LotLine turns that question into a reviewed action sheet in Mattermost. A Switch agent reconciles stock and shipment rows, a second agent independently checks the draft, and the operations lead resolves an ambiguous label using supplier evidence. The draft, audit, decision and action sheet stay together for the next shift.

Built for **Best Business Workflow** at Flip the Switch.

## Open the browser workbench

Open [workbench/index.html](workbench/index.html) directly in a browser. The standalone file includes the synthetic draft, audit and both decision branches generated by the LotLine engine. Review the audit result, choose a simulated supplier reply, and open or download the action sheet. **Reset preview** lets you compare the other branch. No server, account or installation is needed for this preview.

Run `node workbench/build.mjs` to regenerate the standalone file after modifying the fixture, engine or layout. For live agents and chat identity, follow the Switch setup below.

## 1. Run the local checks

Install **Node.js 22 or newer**. Clone the public project repository or extract the source ZIP. Open a terminal in the folder containing this README. No npm install is needed.

```text
node --version
node --test
node src/lotline.mjs fixtures/ll-017.json
```

All tests should pass. The sample draft shows **36 shipped / 18 in stock confirmed** and **40 shipped / 6 in stock pending**. Save the complete 64-character value after `Sheet SHA-256` if you want to exercise the workflow locally:

```text
node src/lotline.mjs audit fixtures/ll-017.json "<draft-sha256>"
node src/lotline.mjs finalize fixtures/ll-017.json "<draft-sha256>" "<audit-receipt>" include ops.lead NS-SUP-017-A
```

Replace the quoted placeholders with the actual draft value and the receipt printed by `audit`. Change `include ops.lead NS-SUP-017-A` to `exclude ops.lead NS-SUP-017-B` to test the other outcome. Use this CLI path to verify the calculations and receipt checks. Continue to Step 2 for the chat workflow.

## 2. Start Switch and Mattermost

1. Install and start Docker if you plan to use bundled Mattermost. Open Switch Console and select **Get started → On this computer → Start**. Alternatively, join an existing Switch server with a working Mattermost connection. [Switch quickstart](https://docs.switchagents.ai/switch-rooms/getting-started)
2. Make sure Codex, Claude Code or OpenCode is installed and signed in on the machine that will run the agents. The walkthrough uses Codex. Node.js and this project must be on that same machine.
3. In Switch Console, open the server's **Home → Messaging apps**. Open the menu on the Mattermost row and choose **Sign-in details** to open Mattermost. Use the linked Mattermost account of the Switch user who will deploy the template. Link the account if Switch asks. [Mattermost setup](https://docs.switchagents.ai/switch-rooms/deploy/messaging-apps/mattermost)

## 3. Deploy the room

1. In Switch Console, select **Templates → Import template**. Open [switch/lotline.template.yaml](switch/lotline.template.yaml), then select **Use**. [Switch template guide](https://docs.switchagents.ai/switch-rooms/administer/room-templates)
2. Select your provider, agent machine and the **Mattermost** bridge. Enter the absolute path to the folder containing this README as the project directory. On Windows, use the path as shown in Explorer, without enclosing quotes.
3. Leave the prefix as `lotline` for these examples. Choose a new prefix if those names are taken, and substitute it in all mentions. The operator label defaults to `ops.lead`. This is the label printed on the sheet, while the actual author's identity is in the chat.
4. Create the agents and room. Open the resulting private Mattermost channel, `lotline-recall-desk`. Run `!list-agents` to confirm both agents are present. Keep the agent machine online.

## 4. Run the live case

1. Post this as a new Mattermost message.

   ```text
   @lotline-reconcile Review LL-017.
   ```

2. Open its thread. Wait for the draft and the auditor's `AUDIT LL-017 PASS` with the full draft fingerprint and receipt. If the handoff does not wake the auditor, post this as the deployer **in the same thread**, replacing the placeholder with the draft fingerprint.

   ```text
   @lotline-audit Verify LL-017 draft <draft-sha256>.
   ```

3. Read the [simulated supplier replies](fixtures/supplier-replies.md). Pick one. After PASS, post the corresponding line as a **new reply to the same thread** from the deployer's Mattermost account.

   ```text
   @lotline-reconcile DECISION LL-017 INCLUDE K7-20Z EVIDENCE NS-SUP-017-A
   ```

   Or:

   ```text
   @lotline-reconcile DECISION LL-017 EXCLUDE K7-20Z EVIDENCE NS-SUP-017-B
   ```

4. Check the final action sheet against this table. A fresh run of the other branch needs a new root message and audit.

   | Scope | Confirmed shipped | Confirmed in stock | Pending shipped | Pending in stock |
   | --- | ---: | ---: | ---: | ---: |
   | Draft | 36 | 18 | 40 | 6 |
   | Include | 76 | 24 | 0 | 0 |
   | Exclude | 36 | 18 | 0 | 0 |

   `OUT-103` (Hill Store) and `STK-202` (West DC) change with the decision. `OUT-105` stays excluded in both branches because it is a different SKU. The final sheet shows the draft fingerprint and the audit receipt so you can match it to the earlier PASS.

## 5. Rehearse the failure paths

- **Missing audit.** In a fresh thread, send a decision before PASS or from outside the review thread. The agent instructions require a new, in-thread decision after PASS.
- **Changed inventory.** Run the local draft and audit, make a separate copy of the fixture, change a quantity in that copy and try to finalize it with the original fingerprint and receipt. The CLI exits with an audit mismatch and produces no action sheet.
- **Wrong receipt.** Use the original fixture but change one character of the receipt. Finalization fails.
- **Agent silent or unable to run a command.** Check `!agents-status`, the linked deployer account, the machine and provider sign-in, the configured directory and Node availability. If Switch requests permission for a fixed read-only LotLine command, inspect it before allowing it. [Switch troubleshooting](https://docs.switchagents.ai/switch-rooms/resources/troubleshooting)

## How it works

| Responsibility | Implementation |
| --- | --- |
| Chat, identities, shared policy and handoff | Switch room template and Mattermost bridge |
| Draft calculation | `src/reconcile.mjs` classifies each row and totals shipped and stock separately |
| Independent verification | `src/workflow.mjs` partitions by SKU and lot, independently classifies rows, and uses exact integer sums before comparing the draft fingerprint |
| Scope decision | The linked operator consults the supplier and posts their decision after the audit |
| Final sheet | The CLI rechecks the audit against the current inputs and records the decision, row IDs and proposed actions |

The fingerprint covers the validated notice, every inventory row, the row classifications and the totals. Reordering JSON keys or rows does not invalidate it. Changing a quantity, lot, SKU, destination or record kind does. The receipt verifies content consistency. It is reproducible and carries no signature. The live workflow relies on Switch addressing and agent instructions for checking the author and thread. The terminal commands are available for local reproduction and do not authenticate chat authors.

The live template targets the supplied synthetic case. The CLI accepts the same JSON shape for other cases. Supply a notice with an exact SKU, confirmed lot and distinct questionable lot. Inventory rows need unique case-sensitive IDs, exact SKU, lot, destination, `kind` (`shipped` or `stock`) and a positive whole-unit count. The export must count each physical unit once. Spaces, hyphens and case are ignored for lot matching. Letters and digits remain distinct. An empty export is treated as incomplete, and an export with zero matching questionable rows needs no scope decision. The sheet is an internal review artifact. Staff perform any inventory or customer actions separately.
